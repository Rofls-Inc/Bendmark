# load_agent

Генератор HTTP-нагрузки: шлёт GET-запросы с заданной частотой, замеряет задержки и пишет агрегированную статистику ступени в JSON.

## Сборка

```bash
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . -j
```

Нужны: CMake ≥ 3.16, C++17, libcurl с заголовками (`libcurl4-openssl-dev` на Debian/Ubuntu).

## Docker

Из корня репозитория, вместе с ABStock в общей сети:

```bash
docker compose up -d --build abstock
docker compose run --rm agent http://abstock:8080/ 50 10
```

Образ собирается в два этапа: в первом есть компилятор, CMake и заголовки libcurl, во второй попадают только бинарник и `libcurl`.

## Запуск

```
./load_agent <URL> <rate_per_sec> <duration_sec> [options]
```

Пример:

```bash
./load_agent https://example.com 100 45 --concurrency 64 --json result.json
```

## Опции

| Опция | По умолчанию | Описание |
|---|---|---|
| `--concurrency N` | `16` | Число потоков-воркеров, то есть максимум одновременных запросов |
| `--timeout MS` | `5000` | Таймаут одного запроса, мс |
| `--output FILE` | stdout | Куда писать задержки (одна на строку, мс) |
| `--json FILE` | — | Куда писать агрегированную статистику |

## Что именно измеряется

Задержка считается **от запланированного момента отправки** до ответа или таймаута, как требует контракт (`proto/README.md`, поле `latency_ms`).

Планировщик тикает с заданной частотой. На каждом тике:

- если есть свободный воркер, запрос уходит сразу, и задержка почти совпадает со временем ответа сервиса;
- если все воркеры заняты, запрос **не отправляется и не ставится в очередь**, а увеличивает `skipped_count`.

Пропуск означает, что агент не смог подать заданную нагрузку. Ставить такие запросы в очередь нельзя: агент молча снизил бы нагрузку на сервис, а `throughput_rps` всё равно показал бы заданную частоту. Поэтому ступень с `skipped_count > 0` — недостоверный замер, и анализатор её отклоняет.

Так два случая различаются:

| Что происходит | Что видно в результате |
|---|---|
| Сервис замедлился | Растёт задержка, `skipped_count = 0` |
| Агенту не хватает воркеров | `skipped_count > 0`, ступень недостоверна |

## Выбор concurrency

`concurrency ≥ rate × задержка_в_секундах`, с запасом ×2–4. Например, при 400 запр/с и ответе за 50 мс нужно не меньше 20, лучше 40–80.

Если сервис под нагрузкой начинает отвечать дольше, воркеров нужно больше. Пропуски, появившиеся на высоких ступенях, — сигнал увеличить `--concurrency` и повторить прогон.

## Вывод

**Задержки** — в stdout или в `--output`, по одной на строку, в мс с точностью до микросекунды (только успешные):

```
12.483
11.902
13.771
```

**Ошибки** — в stderr:

```
request failed: HTTP 500 (after 12.4 ms)
request failed: Couldn't resolve host name (after 3.1 ms)
```

**Пропуски** — в stderr:

```
[warn] skipped 632 of 1200 planned requests: all 8 workers were busy.
[warn] The step is not a valid measurement of the service (the analyzer rejects skipped_count > 0). Increase --concurrency to at least rate x latency.
```

**JSON** (`--json result.json`):

```json
{
  "target_rps": 100,
  "duration_seconds": 45,
  "request_count": 4500,
  "throughput_rps": 100,
  "latency_ms": { "p50": 12, "p90": 18, "p99": 22 },
  "errors": { "count": 0, "rate_percent": 0 },
  "skipped_count": 0
}
```

| Поле | Описание |
|---|---|
| `target_rps` | Заданная частота |
| `duration_seconds` | Заданная длительность |
| `request_count` | Завершившиеся попытки: успехи, HTTP-ошибки и таймауты. Пропуски не входят |
| `throughput_rps` | `request_count / duration_seconds` |
| `latency_ms.p50/p90/p99` | Перцентили задержки от запланированного момента, по всем попыткам (nearest-rank) |
| `errors.count` | HTTP 4xx/5xx, таймауты и транспортные ошибки |
| `errors.rate_percent` | Доля ошибок от `request_count`, % |
| `skipped_count` | Тики, которые не были отправлены, потому что все воркеры были заняты |

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Хотя бы один запрос успешен |
| `1` | Ошибка аргументов или файла |
| `2` | Все запросы провалились |
| `3` | Ни одного запроса не отправлено (в том числе если пропущены все) |
