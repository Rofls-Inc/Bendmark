# Эмулятор тестируемого HTTP-сервиса

Сервис служит отдельной целью для нагрузочных агентов Bendmark ([задача #76](https://github.com/Rofls-Inc/Bendmark/issues/76)).

В режиме `healthy` обычный запрос возвращает `200` после заданного времени обработки.
В режиме `reject` одновременно обрабатывается до `-workers` запросов.
Если все места заняты, новый запрос сразу получает `503` без ожидания в очереди.
Успешный ответ содержит `{"status":"ok","mode":"healthy"}` или `{"status":"ok","mode":"reject"}`.
Путь, метод и содержимое обычного запроса не влияют на нагрузку.
`GET /health` сразу возвращает `200` и `ok`, без задержки обработки.
Отмена запроса прерывает ожидание задержки.

## Локальный запуск

Нужен Go 1.24 или новее. Из корня репозитория:

```powershell
cd services/emulator
go run . -service-time=50ms
```

В другом терминале:

```powershell
curl.exe http://127.0.0.1:8083/health
curl.exe -X POST http://127.0.0.1:8083/work
```

Для запуска с ограничением выполните `go run . -mode=reject -workers=4 -service-time=100ms`.
Расчётная пропускная способность пула равна числу обработчиков, делённому
на время обработки в секундах: `4 / 0,1 = 40 запросов/с`.
Фактический момент появления отказов зависит от распределения запросов
во времени и накладных расходов сервера.

Остановка — `Ctrl+C` в терминале сервера.

| Флаг | Переменная окружения | По умолчанию |
| --- | --- | --- |
| `-listen` | `EMULATOR_LISTEN` | `127.0.0.1:8083` |
| `-mode` | `EMULATOR_MODE` | `healthy` |
| `-service-time` | `EMULATOR_SERVICE_TIME` | `50ms` |
| `-workers` | `EMULATOR_WORKERS` | `4` |

Флаги имеют приоритет над переменными окружения. Настройки применяются при старте.
При запуске сервер выводит адрес, режим и время обработки в лог.
В режиме `reject` он также выводит размер пула и его расчётную пропускную способность.
Адрес по умолчанию доступен только с самого ноутбука: подключение Docker-агентов
и публикация порта будут настроены вместе с Docker Compose.
