# Эмулятор тестируемого HTTP-сервиса

Сервис служит отдельной целью для нагрузочных агентов Bendmark ([задача #76](https://github.com/Rofls-Inc/Bendmark/issues/76)).

В режиме `healthy` обычный запрос возвращает `200` после заданного времени обработки.
В режиме `reject` одновременно обрабатывается до `-workers` запросов.
Если все места заняты, новый запрос сразу получает `503` без ожидания в очереди.
В режиме `saturation` запросы могут ждать в очереди свободного обработчика,
затем обрабатываются за обычное время. Это даёт рост задержки при заполнении пула.
В режиме `slow` запрос, который ждал в очереди, дополнительно занимает
обработчик на `-slow-delay`. Это имитирует резкое замедление под нагрузкой.
В обоих режимах очередь вмещает до `-queue-size` запросов. При её заполнении
следующий запрос получает `503`. Пока очередь не заполнена и клиент
дожидается ответа, `saturation` возвращает обычные успешные ответы.
Успешный ответ содержит `status: ok` и активный `mode` в JSON.
Путь, метод и содержимое обычного запроса не влияют на нагрузку.
`GET /health` сразу возвращает `200` и `ok`, без задержки обработки.
Отмена запроса освобождает место в очереди или в пуле.

## Лаборатория в Bendmark

Поднимите стенд командой `docker compose --profile emulator up --build` и откройте
http://localhost:5173/lab. Выберите режим, при необходимости измените параметры
обработки и нажмите **«Применить настройки»**. Затем можно сразу запустить
пример или открыть заполненную форму и настроить нагрузку.

Координатор применяет настройки через `PUT /emulator/config` между прогонами.
Они действуют до перезапуска процесса эмулятора, после которого берутся из его
аргументов и переменных окружения. В Compose сбор телеметрии для этой цели включён
по умолчанию.

## Локальный запуск

Нужен Go 1.24 или новее. Из корня репозитория:

```powershell
cd services/emulator
go run . -service-time=50ms
```

В другом терминале:

```powershell
curl.exe http://127.0.0.1:8083/health
curl.exe -X POST http://127.0.0.1:8083/work
```

Для запуска с ограничением выполните `go run . -mode=reject -workers=4 -service-time=100ms`.
Для проверки ожидания используйте `go run . -mode=saturation -workers=1 -queue-size=4 -service-time=500ms`
и отправьте несколько запросов к `/work` параллельно.
Для резкого замедления используйте `go run . -mode=slow -workers=1 -queue-size=4 -service-time=500ms -slow-delay=5s`.
В `slow` запросы из очереди при такой настройке могут превысить стандартный
пятисекундный таймаут агента.

Чтобы добавить небольшой разброс и редкие выбросы в любом режиме:

```powershell
go run . -service-time=50ms -jitter=20ms -outlier-rate=0.02 -outlier-delay=800ms -seed=42
```

Каждый принятый в обработку запрос получает от 0 до 20 мс дополнительной
задержки. С вероятностью 2% он также получает ещё 800 мс. Время ожидания
обработчика и дополнительная задержка режима `slow` считаются отдельно.
`GET /health` и немедленные ответы `503` не получают искусственную задержку.
При одинаковых настройках и `seed` последовательность случайных задержек
повторяется. При параллельной нагрузке порядок начала обработки запросов
и измеренное сетевое время могут отличаться.

Расчётная пропускная способность пула без дополнительной задержки равна числу обработчиков, делённому
на время обработки в секундах: `4 / 0,1 = 40 запросов/с`.
Фактический момент появления отказов зависит от распределения запросов
во времени и накладных расходов сервера.

Остановка — `Ctrl+C` в терминале сервера.

| Флаг | Переменная окружения | По умолчанию |
| --- | --- | --- |
| `-listen` | `EMULATOR_LISTEN` | `127.0.0.1:8083` |
| `-mode` | `EMULATOR_MODE` | `healthy` |
| `-service-time` | `EMULATOR_SERVICE_TIME` | `50ms` |
| `-workers` | `EMULATOR_WORKERS` | `4` |
| `-queue-size` | `EMULATOR_QUEUE_SIZE` | `32` |
| `-slow-delay` | `EMULATOR_SLOW_DELAY` | `5s` |
| `-jitter` | `EMULATOR_JITTER` | `0s` |
| `-outlier-rate` | `EMULATOR_OUTLIER_RATE` | `0` (вероятность от 0 до 1) |
| `-outlier-delay` | `EMULATOR_OUTLIER_DELAY` | `0s` (при положительной вероятности задайте положительную задержку) |
| `-seed` | `EMULATOR_SEED` | `1` |

Флаги имеют приоритет над переменными окружения. Настройки применяются при старте.
При запуске сервер выводит адрес, режим и время обработки в лог.
В режимах с пулом он также выводит размер пула и его расчётную пропускную
способность до перегрузки.
При локальном запуске адрес по умолчанию доступен только с самого ноутбука.

## Docker Compose

Из корня Bendmark запустите стенд с профилем `emulator`:

```powershell
docker compose --profile emulator up --build -d --wait --wait-timeout 180
curl.exe -f http://127.0.0.1:8083/health
```

В [интерфейсе Bendmark](http://localhost:5173) укажите `http://emulator:8080/work`
в качестве цели. С ноутбука эмулятор доступен по `http://127.0.0.1:8083`.
Обычный `docker compose up` без профиля эмулятор не запускает.

Чтобы сменить режим, передайте переменные окружения и обновите только эмулятор:

```powershell
$env:EMULATOR_MODE = 'reject'
$env:EMULATOR_WORKERS = '4'
$env:EMULATOR_SERVICE_TIME = '100ms'
docker compose --profile emulator up -d --wait emulator
```

Compose передаёт параметры из таблицы, кроме `EMULATOR_LISTEN`: в контейнере
эмулятор слушает `0.0.0.0:8080`. Проверка запускает `/emulator -healthcheck`
с адресом `http://127.0.0.1:8080/health`, ждёт до двух секунд и завершается
с ошибкой, если сервер недоступен или ответил кодом отличным от `200`.

Чтобы остановить стенд, выполните `docker compose --profile emulator down`.

## Телеметрия

`GET /telemetry` отдаёт [снимок версии 1](../../docs/telemetry.md). В нём видны
занятые обработчики, длина очереди и накопленные числа обработанных и отклонённых
запросов. В `healthy` поля пула и очереди равны `null`, в `reject` равны `null`
только поля очереди. У существующей пустой очереди длина равна `0`.
Запросы к `/health` и `/telemetry` обходят пул и не входят в счётчики нагрузки.

Чтобы координатор сохранил снимки в отчёте, запустите из корня репозитория:

```powershell
$env:EMULATOR_MODE = 'saturation'
$env:EMULATOR_WORKERS = '2'
$env:EMULATOR_QUEUE_SIZE = '4'
$env:EMULATOR_SERVICE_TIME = '250ms'
$env:Telemetry__Url = 'http://emulator:8080/telemetry'
docker compose --profile emulator up --build -d --wait --wait-timeout 180
curl.exe -f http://127.0.0.1:8083/telemetry
```

Запустите сценарий с целью `http://emulator:8080/work`. Снимки доступны
в `telemetry.snapshots` ответа `GET /runs/{id}` на порту координатора `5080`.
Например, с настройками выше нагрузка 21 запрос/с заполняет очередь и приводит к
отказам. Для ABStock сбор остаётся выключенным, если настроен только источник
эмулятора.

## Как читать результаты режима `saturation`

Сейчас агент ждёт завершения запросов после окончания окна ступени и делит
число всех попыток, включая ошибки и поздние ответы, на заданную длительность.
Поэтому плато фактической скорости ответов эмулятора может не отображаться
в `throughput_rps`. Отдельный замер скорости ответов отслеживается в [#89](https://github.com/Rofls-Inc/Bendmark/issues/89).
Подтверждение насыщения по заполненности пула и очереди входит в [#92](https://github.com/Rofls-Inc/Bendmark/issues/92).
