# Эмулятор тестируемого HTTP-сервиса

Первая часть [задачи #76](https://github.com/Rofls-Inc/Bendmark/issues/76).
Сервис служит отдельной целью для нагрузочных агентов Bendmark.

Сейчас реализован режим `healthy`: любой путь и HTTP-метод возвращают
`200` с JSON `{"status":"ok","mode":"healthy"}` после заданного времени обработки.
Содержимое запроса не влияет на ответ. Искусственного ограничения числа
обработчиков пока нет; фактическая производительность зависит от машины.
`GET /health` сразу возвращает `200` и `ok`, без задержки обработки.
Отмена запроса прерывает ожидание задержки.

## Локальный запуск

Нужен Go 1.24 или новее. Из корня репозитория:

```powershell
cd services/emulator
go run . -service-time=50ms
```

В другом терминале:

```powershell
curl.exe http://127.0.0.1:8083/health
curl.exe -X POST http://127.0.0.1:8083/work
```

Остановка — `Ctrl+C` в терминале сервера.

| Флаг | Переменная окружения | По умолчанию |
| --- | --- | --- |
| `-listen` | `EMULATOR_LISTEN` | `127.0.0.1:8083` |
| `-mode` | `EMULATOR_MODE` | `healthy` (пока единственный режим) |
| `-service-time` | `EMULATOR_SERVICE_TIME` | `50ms` |

Флаги имеют приоритет над переменными окружения. Настройки применяются при старте.
При запуске сервер выводит адрес, режим и время обработки в лог.
Адрес по умолчанию доступен только с самого ноутбука: подключение Docker-агентов
и публикация порта будут настроены вместе с Docker Compose.

## Следующие части задачи

1. Ограниченный пул обработчиков и быстрый отказ `503` (`reject`).
2. Модели очереди и задержек для `saturation` и `slow`.
3. Шум, выбросы и воспроизводимые случайные решения.
4. Dockerfile, проверка здоровья из бинарника и профиль Compose `emulator`.
5. Сценарии и проверка ожидаемого предела и диагноза через весь Bendmark.

Задача #76 целиком ещё не завершена. Управление из UI и сбор телеметрии — отдельные расширения.
