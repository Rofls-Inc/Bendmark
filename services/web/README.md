# web

Веб-интерфейс. TypeScript, React, Vite.

Экраны по макетам `assets/mvp-*.webp`:

- **Сценарий** (`/`) — цель и ступени «от / до / шаг», план прогона. Отправляет сценарий в `POST /runs`, ошибки координатора показывает у полей формы.
- **Прогон** (`/runs/{id}`) — пока прогон не завершён, раз в 2 секунды опрашивает `GET /runs/{id}`. Показывает ступень и время по часам от `started_at`, графики задержки (p50/p90/p99) и пропускной по пришедшим ступеням, таблицу ступеней. Кнопка «Остановить» вызывает `POST /runs/{id}/stop` после подтверждения: на `202` опрос продолжается до итога, на `409` показывается причина.
- **Отчёт** (тот же адрес, когда статус `completed`, `failed` или `aborted`) — предел, кривая производительности, причины отказа, таблица ступеней. Для `failed` показывает `error`, для `aborted` — сколько ступеней успело пройти. Ступени с `skipped_count > 0` отмечены: агент не успевал отправлять запросы, замер неточный. Кнопки «Повторить» (форма с тем же сценарием) и «Скачать result.json» (`GET /runs/{id}/result`, только `completed` и `aborted`).

API координатора описан в его README (запуск прогона через агента — #33). Предела (`limit`) координатор пока не отдаёт: он появится, когда координатор начнёт вызывать анализатор (#34).

**Недавние прогоны** в боковой панели хранятся в `localStorage` браузера (до 10 штук): у координатора нет списка прогонов, а сами прогоны пропадают после его перезапуска — тогда страница прогона покажет «Прогон не найден».

**Демо** без координатора, на копии `examples/result.json` (`src/demo/result.json`):

| Адрес | Что показывает |
| --- | --- |
| `/runs/demo` | Отчёт, предел 350 запр/с (так считает анализатор на этом файле) |
| `/runs/demo-live` | Идущий прогон, четвёртая ступень |
| `/runs/demo-aborted` | Остановленный прогон, три ступени |
| `/runs/demo-failed` | Сбой агента |
| `/runs/demo-skipped` | Пропуски на последних ступенях |

## Запуск

Нужен Node.js 22. Команды выполняются из `services/web`.

```bash
npm install
npm run dev
```

Интерфейс откроется на http://localhost:5173. Запросы к `/api/*` Vite передаёт координатору на `http://localhost:5080` (запуск координатора - в его README), поэтому CORS не нужен. Другой адрес координатора:

```bash
COORDINATOR_URL=http://localhost:5000 npm run dev
```

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

Тесты на Vitest. Логика идёт в node, компоненты и код, которому нужен браузер (пометка `// @vitest-environment jsdom` в начале файла), — в jsdom через Testing Library, `fetch` подменяется (`src/test/fetch.ts`).

## Docker

Образ собирает статику и раздаёт её через nginx, `/api/` nginx проксирует на `COORDINATOR_URL` (по умолчанию `http://coordinator:5080`, имя сервиса в Docker Compose).

```bash
docker build -t bendmark-web .
```

Сервис для `docker-compose.yml`:

```yaml
  web:
    build: services/web
    ports:
      - "127.0.0.1:5173:80"
    networks: [bendmark]
    depends_on:
      coordinator:
        condition: service_healthy
```
