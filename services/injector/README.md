# Injector (Go)

Первый режим инжектора: TCP-прокси между клиентом и сервером. Он пропускает
данные без разбора протокола и может задерживать ответы сервера. Это позволяет
проверить, как нагрузочный тест реагирует на медленную сеть. Для первой проверки
сервером может быть ABStock; позже прокси можно поставить перед другой сетевой
зависимостью.

## Запуск с ABStock

Сначала запустите ABStock на `http://127.0.0.1:5062`. Затем из
`services/injector` выполните:

```powershell
go run . -listen 127.0.0.1:8081 -upstream 127.0.0.1:5062 -delay 100ms
```

В другом терминале сравните прямой запрос и запрос через прокси:

```powershell
curl.exe -o NUL -s -w "time: %{time_total}s`n" http://127.0.0.1:5062/
curl.exe -o NUL -s -w "time: %{time_total}s`n" http://127.0.0.1:8081/
```

Остановить прокси: `Ctrl+C`. Если ABStock выключен, прокси сообщит об ошибке
подключения, а запрос не пройдёт.

`-delay` добавляется **перед пересылкой каждого полученного от сервера
TCP-фрагмента**. Это не точная задержка на HTTP-запрос: протокол TCP не хранит
границы запросов, и ответ может состоять из нескольких фрагментов. Значение
`0` отключает задержку.
