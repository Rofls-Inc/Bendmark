# Телеметрия: снимок состояния сервиса

Формат ответа `GET /telemetry`, задача [#81](https://github.com/Rofls-Inc/Bendmark/issues/81).
Снимок показывает, что происходит **внутри** нагружаемого сервиса: сколько обработчиков
занято, сколько запросов ждёт в очереди, сколько обработано и сколько отклонено.
Агент видит только внешнюю сторону: задержку и ошибки.

Кто работает с форматом:

- **эмулятор** (Go) отдаёт снимок ([#82](https://github.com/Rofls-Inc/Bendmark/issues/82));
- **координатор** (C#) опрашивает его во время прогона и сохраняет снимки
  ([#83](https://github.com/Rofls-Inc/Bendmark/issues/83));
- **веб** (TypeScript) показывает их в отчёте.

Примеры лежат в [`testdata/telemetry/`](../testdata/telemetry/). Их можно читать
в тестах любого сервиса, не дожидаясь остальных.

## Запрос и ответ

```http
GET /telemetry HTTP/1.1

HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Cache-Control: no-store
```

- **`200`** — снимок в теле. Других успешных кодов нет.
- **Методы, кроме `GET` и `HEAD`,** — `405`. Шаблон `"GET /telemetry"` в `http.ServeMux`
  делает это сам.
- **Ответ не ждёт пул.** Снимок читается из атомарных счётчиков в обход пула
  обработчиков и очереди. Он отвечает и тогда, когда все обработчики заняты, а очередь
  полна. Именно в такие моменты снимок нужнее всего.
- **Технические запросы не считаются.** Запросы к `/health` и `/telemetry` не попадают ни
  в один счётчик снимка и не занимают обработчиков.

## Поля

Имена в `snake_case`, как во всём API координатора.

| Поле | Тип | Единицы | Может быть `null` | Описание |
| --- | --- | --- | --- | --- |
| `schema_version` | целое | — | нет | Версия формата, сейчас `1`. Меняется только при несовместимых изменениях |
| `captured_at` | дата и время | UTC | нет | Когда снят снимок, по часам сервиса |
| `started_at` | дата и время | UTC | нет | Когда запущен процесс сервиса. С этого момента считаются `*_total` |
| `workers_busy` | целое | шт. | да | Сколько обработчиков сейчас обрабатывают запрос |
| `workers_total` | целое | шт. | да | Размер пула обработчиков |
| `queue_length` | целое | шт. | да | Сколько принятых запросов сейчас ждёт свободного обработчика |
| `queue_capacity` | целое | шт. | да | Сколько запросов помещается в очередь. Если очередь полна, новый запрос отклоняется |
| `completed_total` | целое | шт. | да | Сколько запросов с `started_at` обработчик довёл до конца и ответил на них. Неважно, каким кодом ответил |
| `rejected_total` | целое | шт. | да | Сколько запросов с `started_at` сервис отклонил, не передав обработчику: очередь полна или режим отказа |

Два вида полей:

- **Мгновенные** (`workers_*`, `queue_*`) — значение в момент `captured_at`.
- **Накопленные** (`*_total`) — счётчики с момента `started_at`. Они только растут
  и обнуляются только при перезапуске сервиса.

Формат записи:

- Даты и время — строка RFC 3339 в UTC с суффиксом `Z`, например
  `2026-11-17T10:05:12.345Z`. Дробная часть секунд не обязательна, точность — любая.
- Целые — числа JSON, не строки, без дробной части, не меньше нуля.
  До 2⁵³ они читаются без потерь и в JavaScript.

## `null` и `0`

Это главное правило формата: **`0` — измерено, и это ноль; `null` — сервис эту величину
не измеряет или не знает.**

| Значение | Что значит | Пример |
| --- | --- | --- |
| `"queue_length": 0` | Очередь есть, сейчас она пустая | Эмулятор без нагрузки |
| `"queue_length": null` | Про очередь ничего не известно | У источника нет очереди или он её не отдаёт |
| `"rejected_total": 0` | Отказов не было | Сервис справляется |
| `"rejected_total": null` | Отказы не считаются | Отказ сервиса или его режим не учитывается |

Правила для обеих сторон:

1. **Эмулятор пишет все поля всегда.** Если величины нет, пишется `null`, поле
   не пропускается.
2. **Читатель считает пропущенное поле равным `null`.** Тогда ответ другого источника или
   старой версии не превращается в нули.
3. **Неизвестные поля читатель пропускает.** Так новое поле можно добавить, не повышая
   `schema_version`.
4. **Недоступный источник — это не снимок из одних `null`.** Если `/telemetry` не ответил,
   вернул не `200` или не JSON, то снимка за этот момент нет. Как координатор отмечает
   пропуски в отчёте, решается в [#83](https://github.com/Rofls-Inc/Bendmark/issues/83).

### Как объявить поля в коде

Ошибки здесь бывают не в формате, а в типах. Каждый язык по-своему теряет разницу
между `null` и `0`.

**Go**: обычный `int` превращает и `null`, и пропущенное поле в `0`. Нужен указатель.
`omitempty` ставить нельзя: с ним настоящий `0` пропадает из JSON.

```go
type TelemetrySnapshot struct {
	SchemaVersion  int       `json:"schema_version"`
	CapturedAt     time.Time `json:"captured_at"`
	StartedAt      time.Time `json:"started_at"`
	WorkersBusy    *int64    `json:"workers_busy"`
	WorkersTotal   *int64    `json:"workers_total"`
	QueueLength    *int64    `json:"queue_length"`
	QueueCapacity  *int64    `json:"queue_capacity"`
	CompletedTotal *int64    `json:"completed_total"`
	RejectedTotal  *int64    `json:"rejected_total"`
}
```

Время эмулятор пишет через `time.Now().UTC()`, иначе в строке будет смещение пояса,
а не `Z`.

**C#**: `long` на `null` бросает исключение, поэтому нужен `long?`. Имена переводятся
той же политикой, что в `Program.cs` координатора (`JsonNamingPolicy.SnakeCaseLower`).

```csharp
public sealed record TelemetrySnapshot(
    int SchemaVersion,
    DateTimeOffset CapturedAt,
    DateTimeOffset StartedAt,
    long? WorkersBusy,
    long? WorkersTotal,
    long? QueueLength,
    long? QueueCapacity,
    long? CompletedTotal,
    long? RejectedTotal);
```

**TypeScript**: тип пишется как `number | null`. Ловушка в проверках: `0` в условии
считается ложью.

```ts
export type TelemetrySnapshot = {
  schema_version: number
  captured_at: string
  started_at: string
  workers_busy: number | null
  workers_total: number | null
  queue_length: number | null
  queue_capacity: number | null
  completed_total: number | null
  rejected_total: number | null
}

// пропущенное поле (undefined) тоже показываем как «нет данных»
const show = (value: number | null | undefined) => (value == null ? '—' : String(value))

if (s.queue_length) { /* ошибка при пустой очереди сюда не попадём */ }
if (s.queue_length != null) { /* верно значение есть, в том числе 0 */ }
```

## Согласованность значений

В каждом снимке, где оба значения — числа:

- `workers_busy ≤ workers_total`;
- `queue_length ≤ queue_capacity`;
- `started_at ≤ captured_at`.

Поля читаются не одной атомарной операцией. Мгновенные значения в одном снимке могут
отличаться на несколько запросов, которые в этот момент переходят из очереди
к обработчику. Сумма `completed_total + workers_busy + queue_length` поэтому равна числу
принятых запросов лишь приблизительно, проверять её на точное равенство нельзя.

Запрос, клиент которого отключился, пока запрос ждал в очереди, не учитывается ни
в `completed_total`, ни в `rejected_total`. Если таких запросов окажется заметно много,
для них заведём отдельный счётчик.

## Как читать серию снимков

Координатор опрашивает источник по ходу прогона. Скорость считается по разнице двух
снимков с одинаковым `started_at`:

```
скорость обработки = (completed_total₂ − completed_total₁) / (captured_at₂ − captured_at₁)
```

Если `started_at` изменился или накопленный счётчик уменьшился, сервис перезапустился.
Разницу через такой перезапуск считать нельзя. Если в одном из двух снимков счётчик
`null`, скорости за этот промежуток нет.

## Не входит

- Задержка внутри сервиса, CPU и память. Это следующие поля, когда понадобятся.
  Добавляются без повышения версии (правило 3).
- Как часто опрашивать и как хранить снимки. Это решается в
  [#83](https://github.com/Rofls-Inc/Bendmark/issues/83).
- Как эмулятор устроен внутри. Это [#76](https://github.com/Rofls-Inc/Bendmark/issues/76)
  и [#82](https://github.com/Rofls-Inc/Bendmark/issues/82).
